Keys and Secrets Setup Guide

How to create every account, key and secret Agency Hub needs, step by step, and how to hand them over safely.

Agency Hub · Platforms: Firebase, Google Cloud (Sheets), Gmail, n8n, hosting · Version 1.0, October 2026

Before you start

Agency Hub connects to a few outside services. Each one needs its own account and one or more keys. This guide shows where to click to create each key and what to send to the Agency Hub team.

  • Secret values work like passwords. Anyone who has them can read your data or send email as you.
  • Not secret values identify your project. They are safe to share because they are visible in the website anyway.

If Agency Hub hosts the system for you, you only need two sections: section 3 (share your Google Sheet) and section 4 (an email address to send codes from). The Agency Hub team handles the rest.

1. Safe-handling rules

  • Never send secrets by email, WhatsApp, SMS or chat. Use a password manager's secure share (1Password, Bitwarden Send, LastPass) or a one-time secret link that expires after it is opened.
  • Never put secrets in documents, screenshots or code. Key files (.json) go straight from your computer into the secure share, then get deleted from Downloads.
  • One key per purpose. Don't reuse the same password or key in two places, so one can be replaced without breaking the other.
  • Use a company account, not a personal one, so access doesn't leave with an employee. For example, it@youragency.co.il.
  • If a secret leaks, replace it right away. Each section below says how. Then tell the Agency Hub team, so the new value can be installed.

2. Firebase: login and database

Firebase stores user accounts (email/password and Google login) and the agency's data. Create it with the company Google account at console.firebase.google.com. The free Spark plan is enough to start.

2.1 Create the project

  1. Click Create a project, give it a name (for example youragency-hub) and finish the wizard. Google Analytics is optional.
  2. Open Build → Firestore Database → Create database, choose production mode and a region near you (for example europe-west1).

2.2 Turn on login methods

  1. Open Build → Authentication → Get started.
  2. Under Sign-in method, enable Email/Password and Google. For Google, choose a support email and save.
  3. Under Settings → Authorized domains, add the website's address, for example youragency.co.il or youragency.github.io.

2.3 Web app settings Not secret

  1. Open Project settings (gear icon) → General → Your apps → the web icon </>. Register an app named web. Hosting is not needed.
  2. Copy the values from the firebaseConfig box that appears:
    • apiKey, authDomain, projectId, appId

The Firebase apiKey only identifies the project, so it is not a password. Security comes from the login rules and the server.

2.4 Server key (service account) Secret

  1. Open Project settings → Service accounts.
  2. Click Generate new private key → Generate key. A .json file downloads.
  3. Send this file through a secure share (section 1), then delete it from your computer.

This file gives full control of the Firebase project. If it leaks: in the same screen, open Manage service account permissions, find the key under the service account's Keys tab, delete it, and generate a new one.

3. Google Sheets: lead data

Agency Hub reads leads and customers from a Google Sheet. It uses a "reader" robot account (a service account) that can only read the sheets you share with it. It has no other access to your Google account.

3a. If Agency Hub hosts the system (most customers)

  1. Open your sheet in Google Sheets and click Share.
  2. Add the reader email address the Agency Hub team gives you (it ends in .iam.gserviceaccount.com) as Viewer. Untick "Notify people".
  3. Send the team the sheet's link Not secret. The link alone gives no access, because the sheet stays private.

To stop access at any time, remove the reader email from the sheet's Share list.

3b. If you run your own copy: create the reader account

Use console.cloud.google.com. The Firebase project from section 2 already appears there, so select it at the top.

  1. APIs & Services → Library → search for Google Sheets API → Enable.
  2. IAM & Admin → Service Accounts → Create service account. Name it agency-hub-sheets, click Create and continue, skip the role step (no roles needed) and click Done.
  3. Open the new account → Keys → Add key → Create new key → JSON. A .json file downloads Secret.
  4. Copy the account's email (agency-hub-sheets@…iam.gserviceaccount.com) Not secret and share each sheet with it as Viewer (as in 3a).

If Create new key is blocked with a message about an organization policy, your Google Workspace administrator has turned off key creation. Ask them to allow it for this one project (policy iam.disableServiceAccountKeyCreation).

Replace a leaked key: on the service account's Keys tab, delete the old key and create a new one.

4. Gmail: sending signup codes

When someone signs up, Agency Hub emails them a 6-digit code. It needs an email account to send from, ideally a dedicated one such as noreply.youragency@gmail.com.

Option A: Gmail or Google Workspace (simplest)

  1. Sign in to Google as the sending account. If several accounts are signed in, check the profile picture in the corner, because an app password works only for the account that created it.
  2. Turn on 2-Step Verification: myaccount.google.com/signinoptions/twosv.
  3. Open myaccount.google.com/apppasswords, enter the name Agency Hub and click Create.
  4. Copy the 16-letter password Secret. Google shows it only once.
SettingValue
Server (SMTP host)smtp.gmail.com
Port587
Usernamethe full sending address
Passwordthe 16-letter app password, not the normal Gmail password
Sender namefor example Your Agency <noreply.youragency@gmail.com>

"App passwords" missing? Either 2-Step Verification is off, or it's a Google Workspace account whose administrator disabled app passwords. Ask the administrator, or use option B.

Replace a leaked password: delete it on the App passwords page and create a new one.

Option B: an email-sending service

Services like Brevo, Resend or SendGrid deliver more reliably at higher volume. Create an account, verify your domain as they instruct, then copy their SMTP host, port, username and password from the SMTP settings page. They use the same fields as the table above.

5. n8n: AI assistant and automations

n8n runs the workflows, including the chat assistant inside Agency Hub. Use n8n Cloud at n8n.io, or your own server.

5.1 Google Sheets connection inside n8n Secret

On n8n Cloud: go to Credentials → Add credential → Google Sheets OAuth2 API, click Sign in with Google, choose the account that owns the sheets and allow access. No keys need to be copied.

On your own n8n server, create a Google login client first:

  1. In Google Cloud console, enable Google Sheets API and Google Drive API (APIs & Services → Library).
  2. APIs & Services → OAuth consent screen: choose Internal (Workspace) or External, fill in the app name and support email, and add yourself as a test user.
  3. APIs & Services → Credentials → Create credentials → OAuth client ID → Web application. Under Authorized redirect URIs, paste the OAuth Redirect URL shown in n8n's credential window.
  4. Copy the Client ID and Client secret into the n8n credential, then click Sign in with Google.

5.2 AI model key Secret

  1. Example with OpenAI: platform.openai.com/api-keys → Create new secret key → copy it. It is shown only once.
  2. In n8n: Credentials → Add credential → OpenAI → paste the key.
  3. Set a monthly spending limit under the provider's Billing → Limits.

5.3 Chat link for the website Not secret

  1. Open the assistant workflow and its Chat Trigger node.
  2. Turn on Make Chat Publicly Available and set Mode to Embedded Chat.
  3. In Allowed Origins (CORS), enter the website address, for example https://youragency.co.il.
  4. Save, then activate / publish the workflow. The chat only works on the published version.
  5. Copy the Chat URL (it looks like https://…/webhook/…/chat) and send it to the team.

The chat link is visible inside the website, so it is not secret. Keep the workflow limited to reading what the assistant needs.

5.4 Shared secret for future automations Secret

Later phases will let n8n send data to Agency Hub. Both sides then need the same long random value (N8N_SECRET, 32+ characters). Create one with a password manager's generator (64 characters, letters and numbers), then store it in the password manager. It will be pasted into both n8n and the server.

6. Hosting settings

This section applies only if you host Agency Hub yourself. The server (for example on Render, Cloud Run or a VPS) reads its keys from environment variables, which are set in the hosting dashboard and never written in code. On Render this is your service → Environment → Add environment variable. Save, then redeploy.

VariableValue

FIREBASE_PROJECT_IDproject ID from 2.3
FIREBASE_WEB_API_KEYapiKey from 2.3

SHEETS_SERVICE_ACCOUNT_JSONentire contents of the file from 3b Secret

For the two …_JSON variables, paste the whole file content, from the first { to the last }. Pasting just the email address is a common mistake and won't work.

8. Handover checklist

  • Firebase project created with the company account; Firestore in production mode
  • Email/Password and Google login enabled; website domain added to Authorized domains
  • Firebase web config sent (not secret)
  • Firebase service account file sent through a secure share, then deleted locally
  • Google Sheet shared with the reader email as Viewer; sheet link sent
  • Sending email chosen; 2-Step Verification on; app password sent through a secure share
  • n8n: Google Sheets credential connected; AI key added with a spending limit
  • n8n chat: public, Embedded mode, website in Allowed Origins, workflow published; chat URL sent
  • All secrets stored in the company password manager, nowhere else

Questions, or something looks different on screen? Platforms rename menus from time to time. Search the platform's help for the item name in bold, or contact the Agency Hub team. Never send a secret to ask the question.
